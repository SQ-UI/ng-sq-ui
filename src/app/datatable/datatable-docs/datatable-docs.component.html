Datatable with default options

This is the simplest table setup. This example consumes data from jsonplaceholder.typicode.com/todos

  • A collection of todo items is directly passed to the [items] prop. The columns are generated from the keys of the first item.
  • A [paginatorConfig] object is passed (itemsPerPage, currentPage, maxDisplayedPages, lastPage). Here lastPage: 8 announces 40 items while only the first 20 are loaded, to simulate server-side paging: a page that is not loaded yet stays empty until its items arrive.
  • [sortByColumns] is set to allow sorting only by the "id" and "title" columns ([sortByAllColumns] enables every column). Clicking a sortable column cycles ascending → descending → original order; the sort applies to the whole collection, survives page changes, and resets the other columns. (onSortClicked) reports each change.
  • A handler is bound to (pageChange) to load the next chunk of items when a page beyond the loaded ones is requested.

Datatable with custom templates for header and body

This example consumes data from reqres.in/api/users (with bundled sample data as a fallback when the API is unavailable).

  • sq-datatable is used as a container.
  • This example does not use any of the default properties of the datatable.
  • No automatic pagination available, since the presentation depends entirely on the author.
  • The sq-datatable-header and sq-datatable-body directives are used for content projection, respectively for the datatable columns and rows.
@for (col of userItemColumns(); track col) { {{col}} } @for (item of userItems(); track $index) { @for (prop of userItemColumns(); track prop) { {{item[prop]}} } }

Custom datatable using sq-datatable-row and sq-datatable-column

This example consumes data from reqres.in/api/unknown (with bundled sample data as a fallback when the API is unavailable).

  • sq-datatable is used as a container.
  • This example does not use any of the default properties of the datatable.
  • No automatic pagination available, since the presentation depends entirely on the author.
  • The sq-datatable-header and sq-datatable-body directives are used for content projection, respectively for the datatable columns and rows.
  • Each column (th) is represented by a sq-datatable-column component. It requires [name], takes [isSortable], and emits (onSortClicked) with the column name and the direction (true ascending, false descending, undefined original order). Sorting the rows is up to the author, as in the handler of this example. Bind [activeSortColumn] to the name of the sorted column if the other columns should reset their sort icon.
  • Each row (tr) is represented by a sq-datatable-row component which renders the [rowItem] object; pass [columns] to set the column order (by default the row's own keys).
@for (column of resourceItemColumns(); track column.name) { } @for (rowItem of resourceItems(); track $index) { }
