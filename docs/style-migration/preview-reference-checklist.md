**Example ready** means that the real component is rendered and its documented example is available for local inspection. It does not mean every state matches Figma. **Detailed** means saved property-level context exists; **metadata** provides dimensions/structure only; **pending** means the detailed reference is still unread. This checklist uses the source IDs already recorded in the [Phase 1 inventory](phase-1-inventory.md); it does not infer new specifications.

## Cross-component examples

- [x] `previewValidation`: caller-controlled helper/error recovery with linked ARIA state. Uses the verified field base; it is not a new final validation-state design.
- [x] `previewTemplates`: all eight form-template contexts plus custom table header/body, using deterministic data and named remove actions. Decorations are consumer examples, not Figma assets.
- [x] `previewTheme`: local brand/border overrides inherit through a nested `.sq`; the adjacent default theme stays independent; explicit progress colors retain precedence. This demonstrates consumer configuration, with no corresponding Figma theme variant asserted.
- [x] Gallery family headings link directly to the relevant Figma nodes and state their evidence limits.
- [ ] Complete the unread source contexts/screenshots, including dedicated checkbox/radio/chip/menu and state variants.
- [ ] Perform final visual comparison at matching dimensions after fonts load. The browser screenshots establish implementation behavior and geometry, not full Figma fidelity.

No Figma edits, package publication or unsupported-component implementation is part of this checklist. The [styling guide](../styling.md) describes consumer setup; phase reports retain validation evidence and remaining gaps.
